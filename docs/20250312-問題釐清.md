# 空白頁問題釐清

> 2025-03-12

---

## 一、pos-backend 是什麼？

**pos-backend** = 後端 API 服務，部署在 Railway。

- 負責：登入、庫存、結帳、交易、進貨、今日銷售、未結、歷史、同行對帳等
- 前端 `pos/index.html` 透過 `fetch(API_BASE_URL + '/...')` 呼叫
- API 網址：`https://web-production-4ab5e4.up.railway.app/api`

收銀頁能正常運作，代表後端 API 和登入流程是通的，不是「完全缺後端」。

---

## 二、那四個空白頁的資料來源

| 頁面 | 資料來源 | 沒資料時應顯示 |
|------|----------|----------------|
| **未結** | API /pending | 標題「未結帳款」+「無未結帳款」或「載入失敗」 |
| **歷史** | API /history | 標題、日期選擇、統計卡片、表頭、列表區 |
| **今日** | API /today-sales、本地 DB | 標題、統計卡片、列表區 |
| **進貨** | API /inventory (DB.inv) | 分頁、搜尋、分類、商品 grid |
| **設定** | **純靜態 HTML，不依賴 API** | 標題、同步按鈕、公司配件、版本、登出 |

---

## 三、關鍵結論：不是缺資料

**設定頁是純 HTML**，沒有任何 API 或資料庫，照理說一定會顯示：

- 「系統設定」標題
- 同步按鈕
- 公司配件管理
- 版本、登出按鈕

如果連設定頁都是完全空白，代表：

- 不是「缺資料」或「API 沒回傳」
- 而是 **view 本身沒有被正確顯示**（layout / CSS / 顯示邏輯問題）

---

## 四、可能原因（layout / CSS）

1. 切換到這些 view 時，高度被算成 0（flex 或 overflow 設定導致）
2. `display` 或 `visibility` 有誤，元素存在但看不到
3. 元素被壓在畫布外或 z-index 錯誤

收銀頁 (view-pos) 正常，代表 main、header、整體結構沒壞；問題多半出在「有 `hidden` 的 view-section」在被顯示時的 layout。

---

## 五、建議下一步

1. **在瀏覽器開發者工具檢查**：切到「設定」後，選取 `#view-setting`，看 `display`、`height`、`visibility` 等
2. **確認 DOM**：`#view-setting` 是否有 `hidden` class？切換後是否有被移除？
3. **驗證切換邏輯**：`switchView('setting')` 是否有被正確呼叫、是否有 JS 錯誤

釐清後，再針對 layout/CSS 或 JS 做修正。
